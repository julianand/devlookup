# AGENTS.md

# devlookup — GitHub User Search Tool

React 19 + Vite 8 + TypeScript + lucide-react, single package.

## Source of truth
- `README.md` documents the product behavior — the features list and fallbacks (Octocat default, empty-bio/missing-field fallbacks, company-link `@` stripping) define intended behavior; treat it as the behavioral reference when implementing or changing features.
- Icons live in `src/components/Icon.tsx`, a thin wrapper over `lucide-react` (`<Icon name="location" />`); the `IconName` union maps each name to a Lucide component so consumers never import Lucide directly.
- `src/App.css` holds the design-system tokens: a raw palette (`--color-teal-*`, `--color-slate-*`, `--color-white`, `--color-red`), the Inter type scale (`--fs-*/--lh-*/--fw-*`), and semantic theme tokens (`--bg`, `--card-bg`, `--stats-bg`, `--text-*`, `--accent`, `--accent-text`, `--search-bg`, `--icon-meta`, `--error`) with light defaults on `:root` and overrides on `:root[data-theme='dark']`, plus the global `.app`/header skeleton. "Not Available" fallback text uses `--text-muted`. Per-component styles live in colocated `Foo.css` files (`SearchBar.css`, `UserDescription.css`, `ThemeButton.css`) imported by each component; global element styles (body, button, a reset) live in `src/index.css`. Always use the token variables instead of hardcoding colors/fonts.
- Inter is loaded from Google Fonts in `index.html`; `<html>` ships with `data-theme="dark"` (the app defaults to dark).

## Structure
- `src/App.tsx` renders `SearchBar` (props `onSubmit(username)`, `onInput(value)`, `loading`, `searchError`; `onInput` clears the error) and `UserDescription` fed with `userInfo` — the full chain hook → card is live, no dummy data anymore. `SearchBar` is uncontrolled (own input draft read via `FormData` on submit; `name="search-text"`) and renders the "No results" message, disabling the real `disabled` attribute when `loading || searchError`. `UserDescription` (`user?: GithubUser`, `undefined` → empty `.user-card` skeleton) handles the name fallback (`user.name ?? user.login`, without `@`; login repeats below with `@`), the no-bio message, stats via `dl/dt/dd`, and the meta links (company `@x` → `https://github.com/x`, twitter → `x.com`, `linkProps` prefixes `https://` to scheme-less blogs; all links carry `rel="noreferrer noopener"`).
- Data fetching lives in `src/hooks/useUserInfo.ts`: `useUserInfo(defaultUser)` returns `{ userInfo, loading, searchError, loadUser(username), clearSearchError }`. Fetch-on-mount via `useEffect(() => loadUser(defaultUser), [defaultUser])` (with an eslint-disable directive for `react-hooks/set-state-in-effect` — `setLoading(true)` must run synchronously with the fetch start). `loadUser` takes the username as a **parameter** (avoids stale closures), uses a local `AbortController` per call plus a `latest-controller` `useRef` (aborts the in-flight previous fetch; its guards filter aborted fetches so they stay silent — `ctrlRef.current` at rejection time is the NEW controller, so guards must check the local `ctrl`), returns an abort cleanup the mount effect consumes. Types are in `src/interfaces/github-user.interface.ts`.
- Theme toggle is functional via `src/components/ThemeButton.tsx` (`useState` (lazy initializer reading `prefers-color-scheme`, with a `?.` guard for environments without `matchMedia`) + `useEffect` → `document.documentElement.setAttribute('data-theme', …)`). The handler blurs the button after activation (`event.currentTarget.blur()`) — without it, a focused button can be re-activated by stray Space/Enter key events (theme flipping on devtools focus cycles). The toggle label/icon follows the state — the active theme is the *other* one (button shows "Light ☀" while dark is active). Note: `index.html` still hardcodes `data-theme="dark"` before React boots — a system-light user sees a brief dark→light flash (FOUC, accepted nice-to-have).
- SVG icons: `src/components/Icon.tsx` exports a single `Icon` component (`<Icon name="location" />`) backed by `lucide-react` components (search/location/blog/twitter/company/sun/moon → Search/MapPin/Link/X/Building2/Sun/Moon). Each renders a decorative (`aria-hidden`) `currentColor` stroke that inherits color from CSS (user-meta via `--icon-meta`, search via `--accent`, sun/moon via `--text-primary`); "Not Available" items get `opacity: 0.5` via a `unavailable` class on the `<li>`.

## Gotchas
- Testing: Vitest + @testing-library/react + user-event + jsdom are installed. Config lives in `vite.config.ts` (`test: { environment: 'jsdom' }`; no globals — tests `import { describe, it, expect } from 'vitest'`). `npm test` = watch mode, `npm run test:run` = one pass. Tests are colocated next to components (`Foo.test.tsx`). RTL auto-cleanup does not run with `globals: false` — call `cleanup()` in `beforeEach` when a file has multiple tests. Hook tests use `renderHook` (its `unmount` lives on the returned object, not on `result`). Native assertions only (no jest-dom) — `getByRole<HTMLButtonElement>(…).disabled`, not `toBeDisabled()`. Don't use `target.value` narrowing on React events: `target` is `EventTarget`; type the event's generic (`InputEvent<HTMLInputElement>`) and read `currentTarget.value`. Components all use default exports (keep it consistent when adding new ones).
- tsconfig (`tsconfig.app.json`) enforces `verbatimModuleSyntax` (use `import type`), `allowImportingTsExtensions` (relative TS imports need the `.tsx` extension, e.g. `./App.tsx`), and `erasableSyntaxOnly` (no TS enums/namespaces).
- Components live flat in `src/components/`, colocated with their `Foo.css` and `Foo.test.tsx` by prefix; introduce a per-component folder only when a component exceeds ~5 files or gains internal sub-components.
- Test fixtures are centralized in `src/test/github-user.fixture.ts`: `octocatUser` (the canonical API-shape `GithubUser`) and `responseWith(payload, ok?, status?)` (fetch-mock response builder). Never duplicate user fixtures inline in test files — import from it.
- Unauthenticated GitHub API (`https://api.github.com/users/{username}`) is rate-limited (60 req/hr/IP) and returns 404 for unknown users — mock responses in tests (pattern: `vi.stubGlobal('fetch', …)` + `vi.unstubAllGlobals()` in `afterEach`); don't rely on live calls. 404 responses still `res.json()` OK — hook checks `res.ok` and throws to hit the error path.
- `@types/react ≥19.2.10` deprecated `FormEvent`/`FormEventHandler` — use `SubmitEvent`/`SubmitEventHandler` for `onSubmit` and `InputEvent<HTMLInputElement>` for `onInput` (via `currentTarget.value`; `target` is always `EventTarget` in React types). No router, state lib, or CSS framework — plain CSS in `src/App.css`/`src/index.css` unless deliberately added. Icons come from `lucide-react` via the `Icon` wrapper; don't import Lucide directly in components.
